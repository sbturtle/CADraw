# 결정 0013: 프로파일 전체 치수 확인과 확정값 기반 보정

## 상태

채택

## 맥락

ADR-0012가 앱에서 닫힌 프로파일을 보여주기 시작했지만, 그 프로파일은
**보이기만 하고 쓸 수 없었습니다.** `manual_dimensions`는 원에 지름, 호에
반지름, 선에 길이·각도 행을 만들면서 `PolylineEntity`는 건너뛰었으므로
사람이 크기를 확정할 방법이 없었고, 확정이 없으니 `UNRESOLVED`로 남아 DXF에
들어가지 않았습니다.

파고들면 두 번째 문제가 더 근본적이었습니다. `solver._first_scale`은
**확정된 선 길이만** 보정 근거로 인정했습니다. 그래서 확정할 수 있는 특징이
절단 외곽선이나 구멍뿐인 시트는 어떤 값을 입력해도 영원히 보정되지
않았습니다. 이것은 원에도 해당되어, 기존 지름 행 역시 보정을 만들지
못했습니다.

세 번째 문제는 기존 버그였습니다. `confirm_dimension_text`는 입력 텍스트로
kind를 결정하므로, 지름 행에 `240`을 입력하면 원에 붙은 **`LENGTH` 치수**가
되었습니다. `_append_circular_constraint_warnings`는 kind가 맞지 않아
검증을 건너뛰고, `_first_scale`은 `LineEntity`가 아니라 무시했습니다. 즉
사용자가 확정한 지름은 조용히 아무 효력이 없었습니다.

## 결정

### 프로파일은 전체 폭과 높이로 치수화합니다

`DimensionKind`에 `WIDTH`와 `HEIGHT`를 추가했습니다. 레퍼런스 도면이
`600 x 140`, `W=500 H=510`으로 적는 방식 그대로입니다. 두 개가 필요한 이유는
`Dimension`이 `(entity_id, kind)`로 식별되어 한 entity가 같은 kind의 행을
둘 가질 수 없기 때문입니다.

`manual_dimensions`는 **닫힌** `PolylineEntity`에만 두 행을 만듭니다. 열린
체인은 선에서 조립되며 그 선들이 이미 자기 행을 갖고 있습니다.

### 확정된 어떤 크기든 보정 근거가 됩니다

`_first_scale`은 이제 순서대로 시도합니다. 확정된 선 길이 → 닫힌 프로파일의
전체 폭·높이 → 원·호의 지름·반지름. 선을 먼저 보는 이유는 기존 도면이 갖고
있던 스케일을 그대로 유지하기 위함입니다.

프로파일 폭 하나를 확정하면 `scale = 값 / 바운딩 폭`이 되어 모든 non-line
geometry가 `RESOLVED`가 되고 DXF로 나갑니다. 4번 샘플에서 전체 폭 1200mm를
확정하면 스케일 1.3873 mm/px가 잡히고, T자 외곽선이 정확히 1200mm 폭의
17점 `LWPOLYLINE`으로 구멍과 함께 내보내집니다. 그 전에는 아무것도
나오지 않았습니다.

### 행의 kind가 권위를 갖습니다

`confirm_dimension_text`는 파싱된 kind가 `LENGTH`(접두어 없는 맨 숫자)이고
행의 kind가 `WIDTH`/`HEIGHT`/`DIAMETER`/`RADIUS` 중 하나면 **행의 kind를
유지**합니다. `Ø`나 `R` 같은 명시적 접두어가 있으면 파싱 결과를 따릅니다.
그것은 사용자가 행을 잘못 골랐다고 말하는 것이기 때문입니다.

지름이라고 적힌 행에 접두어를 다시 입력하라고 요구하는 것은 불합리하고,
요구하지 않으면 값이 조용히 무력해집니다.

### 두 번째 확정값은 보고하고 적용하지 않습니다

`_append_profile_constraint_warnings`는 확정된 전체 치수를 스케일된 윤곽과
비교해 어긋나면 `CONSTRAINT_MISMATCH`를 남깁니다. 손으로 그린 윤곽의 가로세로
비는 실제 부품과 조금씩 다르므로 폭과 높이는 일반적으로 서로 다른 스케일을
함축합니다. 한쪽이 다른 쪽을 조용히 덮어쓰지 않고 사람이 판단하게 합니다.
원의 지름 검증과 동일한 규칙입니다.

## 이유

`UNRESOLVED`와 DXF 제외의 경계는 그대로입니다. 바뀐 것은 사람이 확정할 수
있는 대상의 범위이며, 확정하지 않으면 여전히 아무것도 내보내지 않습니다.
치수를 만들어내는 규칙은 추가하지 않았습니다.

## 한계

- 보정은 여전히 **단일 전역 스케일**입니다. 프로파일의 폭과 높이를 모두
  확정해도 두 값이 각각 자기 축에 적용되지는 않고, 먼저 확정된 값이 스케일을
  정하고 나머지는 불일치로 보고됩니다. 축별 비균등 스케일이나 닫힌 다각형을
  다루는 constraint solver는 아직 없습니다.
- 전체 치수는 축 정렬 바운딩 박스 기준입니다. 기울어진 부품을 찍은 사진에서는
  바운딩 폭이 부품의 실제 폭보다 큽니다.
- `WIDTH`/`HEIGHT`는 OCR 텍스트에서 파싱되지 않습니다. 손글씨에 폭·높이를
  가리키는 표준 접두어가 없으므로 수동 행으로만 생성됩니다.
- 열린 폴리라인에는 전체 치수 행이 없습니다. 조립된 체인의 각 선이 자기
  길이 행을 갖기 때문이며, 체인 전체를 한 번에 치수화하는 방법은 없습니다.
